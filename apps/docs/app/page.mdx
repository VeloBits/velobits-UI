# VeloBits UI

One token and component layer for every VeloBits surface — the marketing site,
FixMyText, the ToggleFlow dashboard, and the shared Keycloak login theme.

Before this existed, those four had grown **four token vocabularies on the same
Tailwind v4 foundation**, and ~19 icons were byte-identical across two repos.

## Install

Two distributions, one source. Which you want is not a matter of taste:

### npm — for federated and token-only consumers

```bash
npm i @velobits/tokens @velobits/icons @velobits/ui
```

```css
/* your app's CSS — one import */
@import '@velobits/tokens/theme.css';
@source "../node_modules/@velobits/ui/dist";
```

That `@source` line is **not optional**. Tailwind v4 does not scan
`node_modules`, so utilities used inside `@velobits/ui` are never generated and
the components arrive unstyled with no warning anywhere.

**FixMyText must use npm.** Module Federation needs `@velobits/ui` to be a real
singleton so the shell's `TooltipProvider` context reaches into each remote.

### shadcn CLI — for greenfield surfaces

```bash
npx shadcn@latest add https://ui.velobits.dev/r/velobits.json   # everything
npx shadcn@latest add https://ui.velobits.dev/r/button.json     # one component
```

You own the source afterwards. No dependency to bump, and no singleton either —
which is exactly why federated apps should not use this path.

## The three packages

| Package            | What it is                                  | Depends on                   |
| ------------------ | ------------------------------------------- | ---------------------------- |
| `@velobits/tokens` | CSS + TS tokens. **Zero deps, zero React.** | nothing                      |
| `@velobits/icons`  | 88 hand-drawn stroke icons                  | `react` (peer)               |
| `@velobits/ui`     | Components                                  | tokens, icons, react (peers) |

`tokens` is split out because the **Keycloak login theme cannot consume
`@velobits/ui`**: its component sources are git-ignored and re-vended by a
`keycloakify sync-extensions` postinstall hook, so an edit to an unclaimed file
is silently reverted on the next `npm install`. Shared _tokens_ is a clean seam
there; shared _components_ would mean fighting the upstream extension forever.

## Three things that will bite you

**`--primary` is not a text colour.** `#007ACC` measures 3.90:1 on the cream
page — a fill behind white text (4.51:1), and a WCAG failure as text. Links use
`text-link`.

**Lime is asymmetric.** `bg-brand` with `text-on-brand` (charcoal) is 10.89:1 and
is the only sanctioned pairing. Lime _as text_ is 13.24:1 in dark mode and
1.13:1 in light — so `--accent-text` is lime in dark and plum in light.

**Glass is the overlay tier only.** Dialogs, popovers, menus, toasts, sticky
headers. Never page backgrounds, table rows, or anything inside a scroll
container.

## The gate that matters

Every semantic colour pair is asserted against its WCAG target in both themes,
and every glass tier against the seven worst-case backdrops in the palette —
composited in **gamma-encoded sRGB**, because that is what browsers actually do.
Measuring in linear light overstates glass legibility by a wide margin.

A palette edit that breaks contrast fails CI instead of shipping.
